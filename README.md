# stock_agent

🛠️ 시스템 아키텍처 및 핵심 플로우 (System Architecture)현재 에이전트는 단기 추세(1분봉 이동평균선) 추종 및 철저한 리스크 관리(-2% 강제 청산)를 목적으로 설계된 24시간 무인 구동 시스템입니다.  1. 데이터 파이프라인 (Data Pipeline)실시간 호가 수신: bit_socket.py를 통해 빗썸 웹소켓(WebSocket) 서버에 연결하여 초 단위의 실시간 체결 데이터를 수신합니다.  과거 데이터(OHLCV) 수집: coin_ccxt.py와 main_bot.py의 REST API를 통해 최근 30개의 1분봉 캔들 데이터를 주기적으로 폴링(Polling)합니다.  2. 전략 및 판단 엔진 (Strategy Engine)지표 계산: Pandas를 활용하여 실시간으로 단기 5분 이동평균선(MA5)과 장기 20분 이동평균선(MA20)을 연산합니다.  시그널 생성:BUY: 단기선(MA5)이 장기선(MA20)을 상향 돌파하는 골든크로스 발생 시.  SELL: 단기선(MA5)이 장기선(MA20)을 하향 돌파하는 데드크로스 발생 시.  HOLD: 교차점이 발생하지 않은 횡보장 또는 추세 지속 구간.  3. 주문 및 리스크 관리 (Execution & Risk)무결성 서명: 주문 요청 시 파라미터 변조를 막기 위해 SHA-512 해시와 UUID 기반의 JWT 토큰을 실시간으로 생성하여 헤더에 포함합니다.  스탑로스(Stop-Loss): 포지션 보유 중 현재가가 진입가 대비 -2.0% 이하로 떨어지면, 분석 시그널과 무관하게 즉시 보유 수량 전체를 매도하여 시드를 보호합니다.  ⚙️ 에이전트 구동 프로세스 (Execution Steps)자동매매 엔진(main_bot.py)이 실행될 때의 내부 동작 순서입니다.1.환경 초기화 및 검증:Init Phase..env 파일에서 BITHUMB_API_KEY, BITHUMB_SECRET_KEY, TELEGRAM_BOT_TOKEN을 로드하여 API 접근 권한을 확인합니다. veri_telegram.py 로직을 통해 텔레그램 봇 수신함 상태와 Chat ID가 정상인지 1차 검증을 수행할 수 있습니다.2.1분 정각 동기화 루프:Sync Loop.캔들 데이터의 오차를 없애기 위해 무한 루프(while True) 내에서 1회 스텝(시세 조회 -> 분석 -> 주문)을 실행한 뒤, 현재 시각을 측정하여 **다음 1분의 01초 시점까지 정밀하게 대기(sleep)**합니다.3.모의/실전 매매 분기:Execution.전략 시그널이 포착되면 is_paper_trading 변수 상태를 확인합니다.
모의 매매(True)일 경우 가상의 진입가만 메모리에 기록하고 알림을 보냅니다. 실전 매매(False)일 경우 최소 주문 금액 조건(5,000원 이상, 6,000원 기준)을 확인한 뒤 빗썸 서버로 지정가(limit) 주문을 전송합니다.4.모니터링 및 로깅:Logging.이벤트 발생(매수/매도/손절) 시 telegrambot.py 로직을 호출하여 관리자의 스마트폰으로 마크다운 포맷의 실시간 알림을 발송합니다. 동시에 python_log.py를 통해 최대 100MB 크기로 백업되는 로컬 로그 파일(log/trBit.log)에 시스템 상태를 영구 기록합니다.실전 배포 전 주의사항안전한 구동을 위해 최소 며칠간은 반드시 is_paper_trading=True 상태로 텔레그램 시그널과 가상 손익률을 먼저 관찰해야 합니다. 검증이 끝난 후 실전에 투입할 때만 is_paper_trading=False로 변경하여 6,000원의 소액으로 구동을 시작하세요.
